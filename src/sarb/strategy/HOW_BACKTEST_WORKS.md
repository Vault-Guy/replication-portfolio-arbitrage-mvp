# Как работает бэктест: пошаговое описание

Описание написано на конкретном примере: **рынок USA, цель — AAPL**.
Параметры примера: `train_window=252`, `rebalance_frequency=5`, `entry_z=2.0`, `exit_z=0.0`,
`zscore_lookback=60`, `transaction_cost_bps=5`.

---

## Общая идея

Мы берём один актив (AAPL) и строим его **синтетический двойник** — взвешенную комбинацию
других акций, которая максимально близко повторяет поведение AAPL. Разница между настоящим
AAPL и двойником называется **спредом**. Если спред сильно отклонился от нуля — ставим на то,
что он вернётся обратно. Вот и весь смысл стратегии.

---

## Шаг 1 — Входные данные и вселенная активов

**Данные:** дневные цены закрытия ~140 акций США за несколько лет.

**Цель (target):** AAPL — актив, который торгуем.

**Вселенная (universe):** 30 активов, отобранных заранее по приоритетному списку
(MSFT, NVDA, GOOGL, META и т.д.). AAPL из вселенной исключается — иначе двойник просто
скопирует сам себя.

Реальный состав вселенной можно увидеть в `universe_assets` в CSV-результатах.

---

## Шаг 2 — Скользящее окно (rolling window)

Весь временной ряд разбивается на **окна обучения + прогноза**, которые сдвигаются вперёд каждые
`rebalance_frequency` дней.

**Пример для AAPL с 5 годами данных (~1260 торговых дней):**

```
Окно 1:  обучение = дни 1–252    →  прогноз = дни 253–257   (5 дней)
Окно 2:  обучение = дни 6–257    →  прогноз = дни 258–262
Окно 3:  обучение = дни 11–262   →  прогноз = дни 263–267
...
Окно N:  обучение = дни 1008–1259 →  прогноз = день 1260
```

Итого примерно **(1260 - 252) / 5 ≈ 200 окон ребалансировки**.

Важно: обучение всегда на прошлом, прогноз — на будущем. Никакого заглядывания вперёд.

---

## Шаг 3 — PCA и построение синтетического двойника (в каждом окне)

В каждом окне обучения заново строится модель. Вот что происходит внутри:

### 3а. Фильтрация вселенной

Из 30 активов оставляем только те, у которых в окне обучения есть данные в ≥80% строк,
где есть данные по AAPL. Если данных мало — актив выбрасывается. Минимум для продолжения: 5 активов.

Допустим, после фильтрации осталось **25 активов**.

### 3б. Логарифмирование

```
log_price[t, asset] = log(price[t, asset])
```

Все дальнейшие расчёты ведутся в пространстве лог-цен.

### 3в. PCA на вселенной

Берём матрицу лог-цен размером **252 строки × 25 активов**. Стандартизируем каждый столбец
(вычитаем среднее, делим на стандартное отклонение). Запускаем PCA.

PCA находит **главные компоненты** — направления максимальной дисперсии. Берём столько
компонент, сколько нужно чтобы в сумме объяснить ≥80% общей дисперсии (`pca_explained_variance=0.8`).

Пример: первые 6 компонент объясняют 80% — берём их. Получаем 6 "факторов рынка".

### 3г. Регрессия: AAPL → факторы

OLS-регрессия:
```
log(AAPL)_t  =  β₀ + β₁·F₁_t + β₂·F₂_t + ... + β₆·F₆_t + ε_t
```

Где `F₁...F₆` — значения PCA-факторов в момент t. Получаем 7 коэффициентов (intercept + 6).

### 3д. Применение модели на out-of-sample периоде (следующие 5 дней)

Берём реальные цены следующих 5 дней, проецируем через ту же PCA-матрицу,
подставляем в регрессионное уравнение:

```
synthetic_log(AAPL)_t  =  β₀ + β₁·F₁_t + β₂·F₂_t + ... + β₆·F₆_t
```

Это и есть **синтетический двойник AAPL** для этих 5 дней.

Затем окно сдвигается на 5 дней, модель обучается заново — процесс повторяется.

---

## Шаг 4 — Спред

```
spread_t  =  log(AAPL)_t  −  synthetic_log(AAPL)_t
```

Если AAPL вырос сильнее двойника — спред положительный (AAPL "дорогой").
Если двойник вырос сильнее — спред отрицательный (AAPL "дешёвый").

В норме спред должен колебаться около нуля — если два актива действительно ходят вместе.

---

## Шаг 5 — Z-score (осторожно: причинный)

Для торговли нужно понимать: насколько текущее отклонение спреда аномально по историческим меркам?

```
zscore_t  =  (spread_t − mean(spread[t−60 : t−1])) / std(spread[t−60 : t−1])
```

**Важная деталь:** среднее и стандартное отклонение считаются по **предыдущим 60 барам**,
а не включая текущий. Это сделано через `spread.shift(1)` перед rolling-окном.
Иначе мы бы использовали информацию о текущем баре для решения о входе в тот же бар — это читерство.

Первые `zscore_lookback=60` баров дают NaN — торговля там не ведётся.

---

## Шаг 6 — Генерация позиций (entry/exit с гистерезисом)

Торговля происходит баром позже, чем сигнал (сдвиг на 1 бар, шаг 7).
Логика позиций — mean-reversion с гистерезисом:

```
если |zscore| < exit_z (= 0.0):    позиция = 0    (выходим / не входим)
если zscore  > entry_z (= 2.0):    позиция = -1   (шорт спред: AAPL завышен, продаём)
если zscore  < -entry_z (= -2.0):  позиция = +1   (лонг спред: AAPL занижен, покупаем)
если exit_z ≤ |zscore| ≤ entry_z:  позиция = без изменений (держим текущую)
```

**Гистерезис** — это пространство между `exit_z` и `entry_z`. Например при `exit_z=0.0`
мы держим позицию пока |zscore| > 0, то есть пока спред не вернётся точно к нулю.
При `exit_z=0.5` — выходим раньше, не дожидаясь полного возврата.

**Пример хода событий:**
```
день 1: zscore = +1.5  →  нет позиции (не достигли entry_z=2.0)
день 2: zscore = +2.3  →  открываем SHORT (позиция = -1)
день 3: zscore = +1.8  →  держим SHORT (1.8 > exit_z=0.0)
день 4: zscore = +0.4  →  держим SHORT (0.4 > exit_z=0.0)
день 5: zscore = -0.1  →  ЗАКРЫВАЕМ (|-0.1| < exit_z=0.0, т.е. спред перешёл ноль)
```

---

## Шаг 7 — Сдвиг позиции на 1 бар (execution delay)

```
execution_position[t]  =  position[t - 1]
```

Сигнал, сгенерированный по итогам бара `t`, исполняется по цене открытия бара `t+1`.
Это реалистичное допущение: нельзя торговать на той же цене закрытия, на которой получили сигнал.

Из-за этого сдвига первый бар всегда имеет NaN-позицию и не учитывается в P&L.

---

## Шаг 8 — P&L и транзакционные издержки

**Доходность спреда за 1 бар:**
```
spread_return_t  =  spread_t − spread_{t−1}
```

**Валовая доходность стратегии:**
```
gross_return_t  =  execution_position_t × spread_return_t
```

Если в шорте (позиция = -1) и спред упал (spread_return < 0) — зарабатываем.
Если в лонге (позиция = +1) и спред вырос — зарабатываем.

**Транзакционные издержки:**
```
turnover_t    =  |execution_position_t − execution_position_{t−1}|
cost_t        =  turnover_t × (5 / 10 000)   ← 5 bps
net_return_t  =  gross_return_t − cost_t
```

Издержки списываются только при изменении позиции (0→1, 1→0, -1→1 и т.д.).

---

## Шаг 9 — Кривая капитала и метрики

**Кривая капитала:**
```
equity[t]  =  equity[t−1] × (1 + net_return_t)
```
Начинается с 1.0.

**Метрики:**

| Метрика | Формула |
|---------|---------|
| `total_return` | `equity[-1] − 1` |
| `annualized_return` | `(1 + total_return)^(252 / N) − 1`, где N = число баров |
| `annualized_volatility` | `std(net_returns) × √252` |
| `sharpe_ratio` | `annualized_return / annualized_volatility` |
| `max_drawdown` | `min(equity / cummax(equity) − 1)` — всегда ≤ 0 |
| `turnover` | `sum(|Δposition|) / N` |
| `number_of_trades` | число баров, когда позиция изменилась |
| `average_holding_period` | средняя длина непрерывного пребывания в позиции (в барах) |
| `hit_rate` | доля баров с положительным net_return среди активных баров |

**Для крипто** вместо `252` подставляется `8760` (часов в году), т.к. данные часовые и рынок работает 24/7.

## Что перебирается в Grid Search

На каждую комбинацию параметров запускается полный бэктест сверху:

| Параметр | Значения USA | Значения Crypto | Что меняет |
|----------|-------------|-----------------|-----------|
| `rebalance_frequency` | 5, 10, 21, 63 дня | 24, 72, 168, 336 часов | Как часто переобучается модель |
| `entry_z` | 1.0, 1.5, 2.0, 2.5, 3.0 | то же | Порог входа в позицию |
| `exit_z` | 0.0, 0.25, 0.5, 0.75, 1.0 | то же | Порог выхода (всегда < entry_z) |

Фиксированы: `train_window`, `zscore_lookback`, `pca_explained_variance`, `transaction_cost_bps`.

Итого: **4 × 20 = 80 комбинаций на каждый актив**, 80 × 5 активов × 3 рынка = **1200 прогонов**
(некоторые пары entry/exit отбрасываются, если exit ≥ entry — в итоге 1440).

---

## Что реально влияет на результат

**`rebalance_frequency` (частота ребалансировки)**
— чем реже, тем медленнее модель адаптируется к изменениям рынка, но меньше сделок и издержек.
— в крипто r=24 (ежедневно) обычно лучше: рынок меняется быстро.

**`entry_z` (порог входа)**
— высокий (2.5–3.0): мало сделок, каждая с сильным сигналом → меньше шума, но больше ждать.
— низкий (1.0–1.5): много сделок, некоторые — ложные → выше оборот, больше издержек.

**`exit_z` (порог выхода)**
— 0.0: держим позицию до полного возврата спреда к нулю (максимальный потенциал прибыли, но и максимальный риск).
— 0.5–1.0: фиксируем прибыль раньше → меньше риск, но и меньше прибыль.

**`zscore_lookback` (окно z-score)**
— фиксировано: 60 дней для акций, 336 часов для крипто.
— слишком короткое: z-score прыгает, много ложных сигналов.
— слишком длинное: медленно адаптируется к новому уровню спреда.

**`train_window` (окно обучения PCA)**
— фиксировано: 252 дня для акций, 1440 часов для крипто.
— чем длиннее: стабильнее PCA-структура, но медленнее реагирует на структурные сдвиги.

---

## Что сохраняется в результатах (и чего нет)

**Сохраняется:** итоговые метрики (sharpe, return, drawdown и др.) + параметры прогона +
состав вселенной (статический список 30 активов).

**НЕ сохраняется:** коэффициенты регрессии и состав PCA для каждого окна ребалансировки.
Это in-memory данные, которые теряются после завершения прогона.
Чтобы увидеть динамику весов — нужно запустить один конкретный прогон отдельно
и сохранить `replication.metadata` вручную.
