## 2. Логика системы в целом

### Идея стратегии

Система реализует **PCA-репликацию с торговлей спредом** (статистический арбитраж):

1. Для выбранного **целевого актива** (например, AAPL) строится **синтетический аналог** — взвешенная комбинация других активов той же вселенной (MSFT, NVDA, GOOGL...).
2. Синтетический аналог создаётся через **PCA-регрессию**: основные факторы (главные компоненты) вселенной регрессируются на лог-цену целевого актива методом МНК или Ridge.
3. Разница между реальной и синтетической ценой актива в лог-пространстве называется **спредом**. Предполагается, что спред является **стационарным** (mean-reverting).
4. При значительном отклонении спреда (z-score выше порога) открывается позиция в расчёте на возврат к среднему.
5. Обучение модели происходит по **скользящему окну** (walk-forward), чтобы исключить использование будущих данных при построении сигнала.

### Схема обработки данных

```
ZIP-архив (csv/tickers)
        │
        ▼
   Парсинг CSV  ──►  Широкая ценовая панель (DataFrame: время × тикер)
        │
        ▼
  Выбор вселенной  ──►  Список активов (приоритетный + покрытие как fallback)
        │
        ▼
  Walk-forward цикл:
    для каждого rebalance-окна:
      ├── Обучение [t-train_window : t]
      │     └── PCA на вселенной → n компонент → OLS/Ridge регрессия на цель
      └── Out-of-sample [t : t+rebalance_frequency]
            └── Синтетическая цена = intercept + PCA_scores @ beta
        │
        ▼
  Конкатенация OOS-сегментов  ──►  Полный спред и синтетическая цена
        │
        ▼
  Z-score спреда (rolling, каузальный: mean и std считаются по прошлому)
        │
        ▼
  Генерация позиций с гистерезисом:
      z > entry_z  →  позиция -1 (шорт спред: цель дорогая)
      z < -entry_z →  позиция +1 (лонг спред: цель дешёвая)
      |z| < exit_z →  позиция 0  (закрытие)
        │
        ▼
  Сдвиг позиций на 1 бар  ──►  Исключение исполнения на том же баре
        │
        ▼
  Доходность стратегии = позиция × diff(спред) − транзакционные издержки
        │
        ▼
  Метрики: Sharpe, MDD, hit rate, оборачиваемость и др.
```

## 3. Описание модулей

### `src/sarb/data/` — Загрузка данных

#### `base.py`
Общие низкоуровневые утилиты для всех рынков:
- `iter_archive_csv_members()` — итерирует CSV-файлы внутри zip-архива, пропускает `__MACOSX`
- `symbol_from_member()` — извлекает тикер из имени файла, поддерживает обрезку префикса/суффикса
- `read_long_csv()` — парсит CSV в "длинном" формате (одна строка = одна дата + цена), конвертирует индекс в `DatetimeIndex`, устраняет дубликаты (оставляет последнее)
- `build_prices_panel()` — собирает словарь `{тикер: Series}` в широкий `DataFrame`, валидирует
- `clip_prices()` — обрезает панель по диапазону дат
- `apply_missing_value_policy()` — политика пропусков: `"preserve"` (оставить NaN) или `"forward_fill"` (с ограничением длины)
- `validate_canonical_prices()` — проверяет: индекс — DatetimeIndex, нет дубликатов, нет всех-нулевых столбцов, цены строго положительны

#### `usa_loader.py` / `crypto_loader.py` / `russia_loader.py`
Специфичные загрузчики для каждого рынка. Разница:

| Рынок  | Частота | Фактор аннуализации | Политика NaN | Корректировка |
|--------|---------|---------------------|-------------|---------------|
| USA    | 1D      | 252                 | preserve    | Adjusted close (дивиденды, сплиты) |
| Crypto | 1H      | 8760                | preserve    | Нет (сырые цены) |
| Russia | 1D      | 252                 | preserve    | Нет (TradingView) |

Для России дополнительно: очистка символов от запятых (например, `"LKOH, 1D"` → `"LKOH"`), обрезка префикса `RUS_`.

#### `canonical.py`
Слой кэширования: сохраняет и загружает широкие панели в формате **Parquet** через `pyarrow`. Используется для ускорения повторных запусков.

### `src/sarb/universe.py` — Выбор вселенной активов

Приоритетные списки:
- **USA**: 67 тикеров — топ компании по секторам (Technology, Communication, Consumer, Financials, Healthcare, Industrials, Energy, Utilities, Real Estate)
- **Crypto**: 42 токена — крупнейшие по капитализации без стейблкоинов
- **Исключённые токены крипты**: USDT, USDC, DAI, WBTC, WETH, STETH, WSTETH и др.

Алгоритм выбора вселенной (`select_priority_universe`):
1. **USA и Crypto**: берём тикеры из приоритетного списка, которые есть в данных (fuzzy-матч: `BRK.B` ≡ `BRK-B`), до `requested_size` (обычно 30)
2. Если приоритетных не хватает — **fallback**: добавляем активы по убыванию покрытия (наименьший `missing_pct`)
3. **Crypto**: дополнительно фильтруем по временно́му перекрытию с целевым активом (исключаем активы с `overlap < 0.2`)
4. **Russia**: только покрытие, без приоритетного списка
5. Целевой актив **всегда** исключается из вселенной (нормализованное сравнение: `BRK.B` == `BRK-B`)

### `src/sarb/pca_replication.py` — PCA-модель

Ключевые функции:

**`fit_pca_synthetic_etf()`** — обучение модели на тренировочном окне:
1. Отбор активов вселенной с достаточным покрытием (≥ `min_asset_coverage` от строк, где есть цель)
2. Итеративное удаление активов с наибольшим числом NaN до набора нужного количества полных строк
3. Стандартизация вселенных (StandardScaler) → PCA
4. Выбор числа компонент: по порогу объяснённой дисперсии (`pca_explained_variance`) или фиксированное число
5. Регрессия (OLS через `np.linalg.lstsq` или Ridge): `target_log_price = intercept + scores @ beta`

**`apply_pca_synthetic_etf()`** — применение модели к OOS-данным:
- Применяет ранее обученные `scaler.transform()` и `pca.transform()` (без переобучения)
- Возвращает `target_log_price` и `synthetic_log_price` для валидных строк OOS

**`replicate_segment()`** — один rebalance-сегмент: обучение + применение + метаданные

---

### `src/sarb/pipeline.py` — Walk-forward пайплайн

`run_pca_synthetic_etf_pipeline()` организует цикл по всем rebalance-окнам:

```
индекс: [0 ... train_window ... train_window+rebalance ... len]
                 │               │
            train [0:tw]     OOS [tw:tw+rf]
                 │               │
              следующее окно: train [rf:tw+rf], OOS [tw+rf:tw+2rf]
```

Результат: конкатенированный спред, синтетическая цена, реальная лог-цена, таблица метаданных сегментов.

Метаданные каждого сегмента: дата ребалансировки, train start/end, число компонент PCA, объяснённая дисперсия, размер вселенной, статус (`ok`/`skipped`), причина пропуска.

---

### `src/sarb/spread.py` — Спред и z-score

- `compute_spread()` — `spread = log(цель) - log(синтетик)` (выравнивание по индексу)
- `rolling_zscore()` — **каузальный** z-score: в момент `t` берётся история `shift(1)` (т.е. `[t-lookback:t-1]`), вычисляются `mean` и `std`, нормируется текущее значение. Гарантирует отсутствие lookahead.

---

### `src/sarb/signals.py` — Генерация позиций

`generate_positions()` — итерирует по z-score и поддерживает состояние позиции с гистерезисом:

```
|z| < exit_z          →  закрыть позицию (current = 0)
z > entry_z           →  шорт спред (current = -1)
z < -entry_z          →  лонг спред (current = +1)
иначе                 →  удерживать текущую позицию
```

Опциональные выходы:
- `max_holding_period` — принудительное закрытие через N баров
- `stop_loss_z` — стоп-лосс при экстремальном движении против позиции

`shift_positions_for_execution()` — сдвигает позиции на 1 бар вперёд, имитируя исполнение по ценам следующего бара.

---

### `src/sarb/backtest.py` — Бектест

`run_spread_backtest()` — главный оркестратор:
1. Спред → z-score → позиции → execution_positions (со сдвигом)
2. `spread_returns = diff(spread)` — сырые доходности от движения спреда
3. `gross_returns = execution_positions * spread_returns` — P&L без издержек
4. `strategy_returns = gross_returns - |diff(position)| * cost_rate` — P&L после издержек
5. `equity_curve = cumprod(1 + strategy_returns)`
6. Метрики: `PerformanceMetrics`

---

### `src/sarb/metrics.py` — Метрики

| Метрика | Формула |
|---------|---------|
| `total_return` | `equity[-1] - 1` |
| `annualized_return` | `(1 + total_return)^(AF/N) - 1` |
| `annualized_volatility` | `std(returns, ddof=0) × √AF` |
| `sharpe_ratio` | `ann_return / ann_vol` (без вычета безрисковой ставки) |
| `max_drawdown` | `min(equity / cummax(equity) - 1)` |
| `turnover` | `sum(|diff(positions)|) / N` |
| `number_of_trades` | количество ненулевых изменений позиции |
| `average_holding_period` | средняя длина непрерывной позиции в барах |
| `hit_rate` | доля баров с активной позицией и положительной доходностью |

---

### `src/sarb/run.py` — Унифицированный оркестратор

`run_unified_pipeline()` — основная точка входа для одного прогона:
1. Проверяет, что целевой актив не входит в вселенную
2. Создаёт `PCAReplicationConfig` из `RunConfig`
3. Запускает `run_pca_synthetic_etf_pipeline()`
4. Запускает `run_spread_backtest()`
5. Возвращает `UnifiedPipelineResult` с кавеатами

`RunConfig` содержит: рынок, файл данных, частоту, фактор аннуализации, параметры окна, z-score пороги, транзакционные издержки.

**Валидация**: `annualization_factor` должен точно совпадать с ожидаемым значением для данной частоты (252 для "1D", 8760 для "1H"). Несовпадение → `ValueError`.

|----------|-----|--------|--------|
| `train_window` | 252 (1 вариант) | 1440 (1 вариант) | 252 (1 вариант) |
| `rebalance_frequency` | 5, 10, 21, 63 | 24, 72, 168, 336 | 5, 10, 21, 63 |
| `entry_z` | 1.0, 1.5, 2.0, 2.5, 3.0 | ← | ← |
| `exit_z` | 0.0, 0.25, 0.5, 0.75 (< entry_z) | ← | ← |
| Целевые активы | AAPL, BRK.B, MSFT, AMZN, NVDA | BTC, ETH, SOL, XRP, BNB | AFKS, AFLT, LKOH, CHMF, GAZP |

Число комбинаций (для одного рынка): 5 целей × 4 частоты × 16 пар z-score = 320 запусков.

Вселенная выбирается **один раз** на пару `(рынок, цель)` и не меняется при переборе параметров.

Для России: `prices.dropna(how='any')` перед запуском — удаляются строки с любым NaN.

### `src/sarb/strategy/` — Вспомогательные модули стратегии

Эти модули **не подключены** к основному пайплайну и представляют собой альтернативный (незавершённый) подход:

- `ou.py` — калибровка Ornstein-Uhlenbeck процесса: AR(1) на накопленных остатках → оценка `kappa` (скорость возврата), `mu` (долгосрочное среднее), `sigma` (волатильность). Нормализованный OU-сигнал: `(state - mu) / sqrt(sigma^2 / (2*kappa))`
- `pca.py` — PCA-факторная модель с опциональной стандартизацией
- `signals.py` — генерация сигналов по OU с четырьмя порогами (open/close long/short)
- `residuals.py` — накопленные остатки регрессии

### Финансовый бектест (логика)

Бектест реализован в `backtest.py`:

1. **Нет lookahead**: z-score вычисляется только по прошлому, позиции сдвинуты на 1 бар
2. **Транзакционные издержки**: `|Δpositon| × cost_bps / 10000` вычитается за каждую смену позиции

## 7. Системные и логические недостатки

### Критические (влияют на валидность результатов)

#### 1. Look-ahead bias в вселенной USA
`usa_loader.py` явно содержит предупреждение: вселенная из 142 тикеров объединяет топ-100 компаний по состоянию на 2016 и **2026 год**. Это означает, что часть компаний включена в обучение потому, что они выросли до топ-100 к 2026 году — информация, недоступная историческому инвестору. Весь бектест по USA страдает **survivorship bias** и **selection bias**.

#### 2. Коэффициент Шарпа без безрисковой ставки
В `metrics.py` Sharpe ratio вычисляется как:
```python
sharpe_ratio = annualized_return / annualized_volatility
```
Безрисковая ставка **не вычитается**. Для сравнения с опубликованными результатами это некорректно — стандартная формула: `(R - Rf) / σ`. Завышает Sharpe для стратегий с положительной доходностью.

#### 3. Дисперсия с ddof=0 (генеральная совокупность)
```python
annualized_volatility = clean.std(ddof=0) * np.sqrt(annualization_factor)
```
Финансовые метрики традиционно используют `ddof=1` (выборочная дисперсия). При малом числе наблюдений это занижает волатильность и завышает Sharpe.

#### 4. Фиксированная вселенная для всех комбинаций гридсёрча
В `grid_search.py` вселенная выбирается **один раз** на пару `(рынок, цель)` и используется для всех комбинаций `rebalance_frequency`, `entry_z`, `exit_z`. Разные `train_window` (если бы они варьировались) использовали бы одну и ту же вселенную, что некорректно. Кроме того, вселенная выбирается по всей истории данных, а не point-in-time.

#### 5. Нет удержания тестовой выборки (no holdout set)
Весь исторический период используется для гридсёрча. Оптимальные параметры выбираются на тех же данных, по которым оцениваются. Это в-сёрч по историческим данным = **overfitting**. Нет отдельного out-of-sample периода для оценки итоговой стратегии.

#### 6. Нет проверки стационарности спреда
Вся стратегия построена на предположении, что спред является **mean-reverting** (стационарным). Проверка через тест Дики-Фуллера (ADF) или KPSS **не реализована**. Торговля нестационарным спредом — торговля шумом.

### Архитектурные (дублирование и незавершённость)

#### 7. Двойная система загрузчиков
В пакете сосуществуют два параллельных набора загрузчиков:
- `data/crypto_loader.py`, `data/usa_loader.py`, `data/russia_loader.py` — используются основным пайплайном
- `data/loaders/crypto.py`, `data/loaders/usa.py`, `data/loaders/russia.py` — альтернативная архитектура через `BaseMarketLoader`

Они реализуют одинаковую логику, поддерживаются параллельно и рассинхронизируются при изменениях.

#### 8. Модуль `strategy/` не подключён к основному пайплайну
Папка `src/sarb/strategy/` содержит реализации OU-процесса, PCA-факторной модели и сигналов — но основной пайплайн (`run.py`, `pipeline.py`, `backtest.py`) их не использует. Это параллельный незавершённый подход. OU-модель откалиброванная в `ou.py` никуда не передаётся.

#### 9. `walkforward/backtest.py` — заглушка
```python
class BacktestEngine:
    pass  # will implement PnL accounting
```
Модуль объявлен, но не реализован. При этом его имя конфликтует с функциональным `sarb/backtest.py`.

### Методологические

#### 10. `train_window` не варьируется в гридсёрче
Для каждого рынка `train_window` фиксирован (252 для USA/Russia, 1440 для Crypto). Влияние длины обучающего окна на качество репликации не исследуется.

#### 11. `pca_explained_variance` не варьируется
Порог объяснённой дисперсии PCA зафиксирован в YAML-конфигах (0.80 для Crypto, 0.75 для USA). Это один из важнейших параметров модели, но он не включён в гридсёрч.

#### 12. `prepare_market_prices` для России удаляет строки с NaN
```python
def prepare_market_prices(market: str, prices: pd.DataFrame) -> pd.DataFrame:
    if market == "russia":
        return prices.dropna(how="any")
```
`dropna(how='any')` удаляет строку, если **хотя бы один** тикер имеет NaN в этот день. При неполном покрытии (а в России оно часто неполное) это может радикально сократить историю и исказить результаты.

#### 13. Размер вселенной России
Российские данные из TradingView содержат крайне ограниченный набор акций (~15-20). PCA на такой вселенной имеет сомнительное качество из-за малой размерности.

#### 14. Overlap для крипты вычисляется по всей истории, не walk-forward
В `_crypto_enrich_universe_with_overlap()` и `_overlap_scores_for_symbols()` временно́е перекрытие между целевым активом и кандидатами вычисляется по **всем доступным данным**. В walk-forward контексте это вносит lookahead: актив, листингованный позже цели, получает низкий overlap score, основанный на будущих данных.

#### 15. Жёсткая валидация `annualization_factor`
`RunConfig.validate()` требует точного совпадения:
```python
if self.annualization_factor != expected:
    raise ValueError(...)
```
Разные источники данных используют разные конвенции (252 vs 260 vs 261 торговый день). Жёсткая привязка к конкретному числу ломает совместимость без очевидной причины.

#### 16. Sharpe по прогонам с малым числом сделок
В гридсёрче не фильтруются прогоны с единицами сделок. Sharpe ratio на 3-5 сделках статистически бессмысленен, но попадает в `best_by_market.csv` наравне с прогонами с сотнями сделок. Флаги `few_trades` добавляются только в `analyze_grid_search.py`, но не используются при выборе лучших параметров.
